## 9. How I Write Notes

Each note should help me understand a concept and use it independently later.

### Recommended Structure

1. **Definition** — what the concept means.
2. **Intuition** — explanation in my own words.
3. **How it works** — steps or reasoning.
4. **Example** — a small worked example.
5. **Implementation** — code when appropriate.
6. **Complexity** — time and memory costs when relevant.
7. **Common mistakes** — pitfalls and edge cases.
8. **Practice** — problems or exercises.
9. **Summary** — the key ideas to remember.
10. **Related topics** — links to other notes.

Not every note needs all ten sections. Keep it concise when the concept is simple and expand it when the topic is difficult.

### Principles
- Explain ideas in my own words.
- Prefer small examples over long copied explanations.
- Include code that I understand and can reproduce.
- Link related notes instead of duplicating content.
- Update notes when I discover a better explanation.
- Record mistakes because they reveal gaps in understanding.

## 10. Weekly Study Schedule

Target: 8–10 hours per week.

| Day | Focus | Approx. time |
|---|---|---:|
| Monday | Algorithms and new concepts | 1–1.5 h |
| Tuesday | C++ and implementation | 1–1.5 h |
| Wednesday | Python and development | 1–1.5 h |
| Thursday | Algorithmic problem-solving | 1–1.5 h |
| Friday | Revision and difficult problems | 1 h |
| Saturday | A larger problem, project, Git, and notes | 2 h |
| Sunday | Rest or optional light revision | Optional |

### Weekly Targets
- Solve 3–5 new algorithmic problems.
- Revisit 1–2 previously difficult problems.
- Complete one small Python or development exercise.
- Improve at least one note.
- Make meaningful Git commits.
- Review progress and choose next week's priorities.

Adjust the workload during busy weeks. Consistency and understanding matter more than completing every task.
